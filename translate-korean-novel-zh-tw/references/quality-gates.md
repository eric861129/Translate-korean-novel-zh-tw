# 分節校對與全書驗收

分節複核先讀 [檢查要求](#分節複核要求)、[來源覆蓋](#來源與譯文覆蓋)、[問題紀錄](#尚未解決的問題) 及 [登記驗收](#記錄分節驗收)。最後一個交付批次再讀 [全書複核](#全書複核) 與 [交付](#回報與交付)；全書連讀證據從第一批就逐節累積。評分公式與證據格式只由 [評分規準](scoring-rubric.md) 定義，SKILL 開發案例僅於 [維護時](maintenance.md#skill-維護) 閱讀。

## 兩種證據

機械檢查可證明章序、區塊覆蓋、檔案指紋與紀錄一致，無法判斷一句流暢中文是否忠實。語意校對由代理直接閱讀原文與譯文執行；收據是代理聲明，沒有獨立模型判讀或人工保證。

不能為了通過工具而填入並未執行的 `passed`。被追蹤的段落全部有對應，也不代表其中每個語意都譯對；合併段落仍需逐句回查。

## 分節複核要求

本批只完成章內小段時，保存逐段對應、五項校對及問題／修正紀錄，標示 `draft` 或 `self_checked`，不填整節收據。全部小段合併後須完整閱讀並回查接縫，再依 [評分規準](scoring-rubric.md) 填十項分節評分。

`reviews` 的六個鍵均需 `status: passed` 及真實 `note`；小段採下列五個正文檢查鍵，`heading` 留到整節。

| 檢查鍵 | 必須完成的核對 |
|---|---|
| `heading` | 原文標題、章序與分節 |
| `fidelity` | 逐段原意、內容完整性、否定與條件等語意 |
| `referents` | 依 [主詞與指代核對](translation-and-style.md#主詞與你我他她) 確認對話各層的說聽者、動作主客體及你／我／他／她；定稿中文對應一致，高風險處有來源依據，段落及小段接縫已查 |
| `fluency` | 完整中文順讀、對話接續及敘事流暢 |
| `locale` | 繁體字、台灣用語與原作語域 |
| `post_polish` | 潤色後回查韓文，確認原意與資訊未改 |

`referents` 的通過條件包含原文角色關係與最終中文的一致性，不能只核對人名拼寫或代詞字面。無法判定且影響角色／情節的歧義須留為未解問題；已確認的主客體錯誤先修正，平均分數不能抵銷。原作有意模糊而中文忠實保留者，按文體規則在 note 說明即可。小段完成後改動了主詞、引言層級或句子切分，須重新核對受影響範圍及承接摘要；合併分節後仍檢查接縫。

`sections/s0001.txt` 為 UTF-8；第一個非空行是譯後標頭，再接正文。編號標頭如 `第1章 機會（1）`，章號及分節號來自原稿，序章、後記等使用核實的中文名稱。依 [TXT 排版](translation-and-style.md#txt-閱讀排版) 與 [固定範例](../assets/final-layout-example.txt) 統一原文版式，確認對話歸屬、場景界線及特殊結構未受影響，定稿後才建立對應及驗收。

## 來源與譯文覆蓋

工具依代理提供的語意分組計算 `target_lines`：1-based 且包含兩端，可含空白行，不能含標題。小段 map 綁定來源、譯文、詞庫、前後敘事與文體；保存及合併會核對依賴，工具通過不等於語意正確。需要手工修復時才讀 [對應格式](maintenance.md#手工產物格式)。

每個原文區塊只能被一個 entry 引用；所有非空正文行也只能被一個 entry 覆蓋。多段合併成一句時，將原文 IDs 放在同一個 entry，不能讓多個 entry 重複指向同一句。拆句則用連續的起訖行號。

確定為非故事資料才可排除：

```json
{"source_ids":["s0000:p0001"],"disposition":"excluded","reason":"advertisement","note":"此行是來源附加的購書商店網址，位於序章前"}
```

可用 `reason` 為 `advertisement`、`duplicate_heading`、`layout`。不得使用這些分類掩飾漏譯。原作引文、作者附記與場景切換必須翻譯或保留。全數排除的 `preamble` 才能使用空 `.txt` 及 `title_zh: null`；其他分節不能清空交付。

若確有保留韓文的需求，使用 `allowed_hangul` 陣列，逐項填入精確 `text` 與 `reason`。不使用「允許全部韓文」形式的例外。

## 尚未解決的問題

`reviews.jsonl` 每個 issue 一行：

```json
{"id":"issue-001","section_ids":["s0001"],"status":"open","note":"第二段的省略主詞尚需由前後對話確認","evidence":["s0001:p0002"]}
```

修復後改為 `resolved`，補上具體結果。`section_ids: []` 表示影響全書的問題。任何未解決問題都不能進入最終交付；記錄不需修正的觀察時放在校對 note，不製造永遠無法結束的 issue。

## 記錄分節驗收

優先依 [自動保存與共用閱讀](resume-and-delivery.md#自動保存合併與共用閱讀) 執行 `review-section`：先保存實際專名及敘事狀態，對完整分節完成原有六項檢查與十項評分；若同次閱讀也完成結構、專名、連貫性與整節中文連讀，提供真實 `book_reviews`，工具同時登記兩種範圍。它會呼叫與 `record` 相同的分節驗證器，不能用省略檢查來加速。 分節複核可依 [精簡輸入](resume-and-delivery.md#分節複核的精簡輸入) 省略重複欄位名稱；六項實際狀態、指代依據、十項分數及問題紀錄保持完整，工具只展開格式。合併回傳的 complete 表示輸出完整，不是已讀聲明。分節及全書紀錄共用閱讀後，不為填不同表單再重讀相同有效版本。

既有 `record` 手工流程需相同檢查及有效證據，操作與對應格式見 [手工產物格式](maintenance.md#手工產物格式)。任一譯文、對應、專名或敘事依據變更時重新核對受影響範圍，不只更新指紋。

## 最終品質標準

- 原稿全部分節都有有效收據，前置非故事文字有明確排除依據。
- 章序來自韓文，原文同一章名的中文名稱一致；沒有混入舊譯流水標頭。
- 所有具名角色含配角、地名、技能、境界、人物稱呼與揭露時機一致。
- 作者自創動植物及其他設定名稱忠於原文描述，未被強行替換成相似的現實物種。
- 情節、主客體、否定、數量和敘事視角核對完畢。
- 對話中的你我、敘事中的他她、韓文省略主詞與受詞已依當時情節核對；不以後文知識補出尚未揭露的身分或性別。
- 符合台灣繁中用語，保留合理的古代或角色語域；已通順的句子不為潤色而過度改寫。
- 潤色後逐段回查，整節與跨節銜接可自然閱讀。
- 未解決 issue 為零，沒有交給使用者自行修正的占位或提示。
- 每節及全書十項等權平均都達 85 分；評分有實際依據，不以其他高分抵銷已確認的誤譯。

## 全書複核

從第一個 `d` 起，依原稿順序完整閱讀各分節，在同一次閱讀中完成分節與相應全書範圍的檢查，透過 `review-section` 保存綁定版本的 `book_review` 證據。跨批次持續檢查章節目錄、專名、身分揭露與故事連貫性，不以抽查代替全書閱讀。最後一個 `d` 補齊缺口、跨批次一致性與全書評分，已完整讀過且證據仍有效的範圍不重複安排全書逐字重讀；內容或依據失效時則重查受影響範圍。全部覆蓋後才進入 `finalize` 階段並執行 `attest-book` 與 `assemble`，不另增交付批次；實際複核未完時最後一批仍為進行中。

依 [複核進度](resume-and-delivery.md#複核進度) 的 `book_review` 契約逐個 `b` 記錄已覆核範圍、檢查、檔案指紋及下一個位置；未覆蓋範圍不能填 `passed`。有 `batch-plan.json` 的工作目錄，`book-state`、`attest-book` 與 `assemble` 會再核對全部計畫 `b` 的有效閱讀紀錄；舊手工紀錄符合相同契約也可沿用。這仍只能驗證聲明與檔案一致，不能證明代理實際讀完。修正須落回相應譯稿並重新驗收，受影響的複核範圍也重讀。全部複核完成後，才建立下述全書聲明及組裝。先取得目前狀態：

```text
python -X utf8 <skill>/scripts/novel_pipeline.py validate --work <工作目錄>
python -X utf8 <skill>/scripts/novel_pipeline.py book-state --work <工作目錄>
```

建立 `book-review.json`，同時依 [評分規準](scoring-rubric.md) 填寫全書十項評分，平均須達 85 分：

```json
{
  "state": {"將 book-state 回傳物件的全部欄位放在此處": "不要自行計算或省略"},
  "scorecard": {"method": "agent_self_assessment", "items": {}},
  "reviews": {
    "structure": {"status": "passed", "note": "記錄全書章節及來源異常的實際複核結果"},
    "terminology": {"status": "passed", "note": "記錄專名、別名與使用範圍的實際複核結果"},
    "continuity": {"status": "passed", "note": "記錄視角、人物知識、技能層級與跨節銜接結果"},
    "reading": {"status": "passed", "note": "記錄完整中文連續閱讀的範圍與處理結果"}
  }
}
```

範例說明必須換成實際物件與證據，`scorecard.items` 填滿十項分數及各自依據。這份紀錄由代理完成閱讀後填寫，不是工具自動宣告語意正確。

```text
python -X utf8 <skill>/scripts/novel_pipeline.py attest-book --work <工作目錄>
python -X utf8 <skill>/scripts/novel_pipeline.py assemble --work <工作目錄> --output <小說目錄>/<書名>-繁體中文重譯完整版.txt
```

組裝依 manifest 原稿順序與章號，輸出 UTF-8 TXT，依 [TXT 閱讀排版](translation-and-style.md#txt-閱讀排版) 移除獨立場景星號裝飾、不另加替代符號，於新章標題上下加入固定橫線框，同章後續分節不重複加框；每兩個內容行之間統一為 **一個空白行**，包含橫線、標題與分節接縫。去除多餘空行，保留正文文字、標點與順序；外框只屬交付版裝飾。這項固定輸出轉換不回寫已驗收的分節、map 或收據，map 行號仍對應分節檔。工具讀回核對排版後的完整位元內容，再計算最終檔指紋。若發現文字問題，仍回到分節稿修正、重新驗收及組裝。命令的 `--output` 必須使用第二階段保存的 `final_output.path`，不能覆蓋原稿、人工版或放在工作狀態目錄裡。

`assemble` 會拒絕已存在的輸出。恢復時若該路徑已是本次有效交付產物，核對其實際指紋、目前全書收據及組裝內容後沿用；若是其他既有版本或歸屬不明，保留檔案並先釐清處理方式，不為繞過衝突自動產生「最終版2／最終修正版」。若本次產物需要修訂，確認歸屬後以單一明確檔案處理重建，仍維持同一最終路徑。有效讀回後才保存實際 SHA-256；`chunks/`、`sections/`、對應及收據是追溯資料，不各自宣稱另一份最終譯本。

## 回報與交付

提供最終小說路徑、覆蓋的來源範圍、十項最終自評及平均分數、驗收結果。詞庫、逐段對應和工作紀錄保留供追溯，不插入小說正文。若使用者另要 EPUB、DOCX 或 PDF，再依該需求製作，不自動增加交付格式。

只有全部來源範圍有效覆蓋、分節及全書複核完成、未解問題為零、`attest-book` 與 `assemble` 成功，而且唯一最終檔已讀回核對，才保存 `phase: delivered` 與 `final_output.sha256`，若有本任務 Goal，再呼叫 `update_goal(status: complete)`。完成全部初譯、用完預算或只完成批次計畫，都不等於目標達成。

尚未全書完成時依 [進度回報](resume-and-delivery.md#進度回報) 說明有效完成範圍，不把分節數稱為章數或將草稿預覽命名為完整版。
