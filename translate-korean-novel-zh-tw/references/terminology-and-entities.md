# 專名、人物與設定

## 判定順序

先辨認詞在此處是名稱、職稱、能力、境界或普通敘述，再決定譯法。

1. 使用者明確指定的中文名稱優先作為目標譯名；原文情節和身分關係仍照原稿。
2. 原稿明載漢字提供直接證據。區分繁簡、異體與不同漢字；不因字形罕見就換成常見門派或地名字。
3. 原稿沒有漢字時，以人工版穩定使用、與上下文一致的譯名為主要參考。
4. 人工版不一致或與韓文語意衝突時，檢索原稿及人工版各處用法。必要時查可靠字典或專業來源，將連結放證據欄，不放入小說正文。
5. 沒有更強反證時，可以正式採用人工版已有譯名；其依據標成 `human_reference`，不可假稱原作漢字。會影響人物身分、情節或技能含義的未決歧義標 `pending`，先完成其他不依賴它的工作，再查證解決。

例如 `삼성 공력` 在武功成數語境應核對是否為三成功力，不能照抄三星功力；明示的特殊漢字則保留。地名中的疑似原稿錯字，應記錄原字、語意判定與修改理由，不能悄悄改字後把結果當原作證據。

## 候選盤點

全書先找韓文後的漢字括註、反覆出現的稱呼，以及人工版中的人物／技能／組織／地點／境界。抽取只是候選，不把出現頻率當作確定證據。初始盤點支援跨章一致性；隨正式閱讀持續補齊定義和關係。

第一個交付批次先建立足以支援當前原文的名詞表，不必等全書每個詞都定案才開始。後續交付批次先查已採用名稱及適用 `scope`，只對新詞、衝突或新語境補做判定；既有名詞決策可重用以減少重複工作，但每次出現的人物指代、語意及譯名適用範圍仍須核對。

涵蓋人物本名、化名、綽號、尊稱、師承、門派、職位、武器、藥物、技能、修練境界、超自然存在和世界觀概念。一般詞彙只有反覆誤譯或必須固定用法時才納入，避免把詞庫膨脹成字典。

配角與只出場一次的具名角色也要登錄，不只整理主角。角色再出場時先查已採用名稱、別名及稱呼規則；地名、招式、能力與技能層級同樣跨章核對。外觀不同的近音名不能自行合併成同一人物；同一人物的本名、綽號與職稱應透過 `entity_id` 關聯。

主要或反覆出場角色可在既有人物詞條加簡短 `voice_note` 與原文依據，記錄穩定的稱呼、語氣及關係差異，供續譯找回人物聲音。單場景的緊張、偽裝客氣或情緒爆發放在該節敘事紀錄／校對 note，不每次改寫人物的長期設定。名詞表固定的是身分與用法，不能把所有台詞也固定成同一種口吻。

## `terminology.jsonl`

每行一個 JSON 物件。相同實體的多個稱呼可用不同記錄，並以 `entity_id` 關聯；`id` 必須唯一。`ko` 放實際韓文詞形，不要只填帶有括註的完整字串。

```json
{"id":"person-001-name","entity_id":"person-001","ko":["목진"],"zh":"木真","category":"person","decision":"adopted","basis":"human_reference","evidence":[{"source":"reference","line":12,"note":"人工版持續使用此名，原稿未附漢字"}],"scope":{"from":0,"through":8},"forbidden_zh":["穆真"],"definition":"此階段以本名出現"}
```

`scope` 的 `from`／`through` 是 manifest 的 **0-based ordinal**，包含端點；省略即全書適用。不要把它填成原稿章號。`basis` 建議用 `user_choice`、`source_hanja`、`human_reference`、`source_description`、`context_correction`、`external_reference`。`evidence` 包含實際位置、短證據與判定理由，避免大量複製小說。

`decision` 只有 `adopted`／`pending`。缺少原作漢字但已合理採用人工名稱，可為 `adopted`；證據強弱與是否作出決定是不同欄位。

## 詞條的閱讀提醒

詞條的 `definition` 記錄當前身分與含義，`voice_note` 記錄有依據的穩定口吻；稱呼、使用限制或劇情揭露條件需放在可直接閱讀的欄位，不只埋在歷史 evidence。原有自訂提醒欄位會原樣保留。

新詞判定或閱讀中實際發現衝突、多義用法時，可加 `attention`，用 `kind` 標示 `new`、`conflict`、`polysemy` 或 `caution`，`note` 寫具體限制，依據仍存 evidence。例如以下是合成格式：

```json
{"attention":[{"kind":"polysemy","note":"同一稱呼可指人物或職位，須依當節說話者與受話者判斷，不直接套成本名。"}]}
```

非空的提醒會使詞條在精簡閱讀視圖中仍完整顯示。詞形重疊、不同實體同譯名、未決或前序未記錄相同版本的詞條也會提示；工具不替代理裁決語義。已解除的問題依實際查證更新提醒及問題紀錄，不能只為縮短資料包移除提示。提醒本身不取代 `pending` 或 `reviews.jsonl` 的未解問題，也不構成已解決的聲明。

歷史詞庫沒有 attention 時仍相容；工具保留其他欄位，並對既有自由文字的常見限制語句採保守呈現。這些機械提示不保證找到所有歧義，完整原文與按需取得的證據仍須依情境核對。不為開啟精簡功能批次改寫舊詞條；任何真實欄位變動仍依原規則核對受影響收據。操作見 [精簡詞條與完整證據](resume-and-delivery.md#精簡詞條與完整證據)。

## 作者自創的動植物與名稱

動植物、異獸、藥材或其他設定名詞，可能是作者命名的虛構事物。譯名首要忠於小說中的事物與命名，不必使用現實世界已存在的名稱。

先看原稿漢字、首次出場描述、後續用法及人工版名稱。再依下列規則判定：

- 原稿明示為現實物種，或已有充分語境證據，才用可靠資料確認其現實名稱。不能只因韓文相近、功效相似或外觀接近，就套成某種真實植物或動物。
- 原稿顯示為自創物種，或作者的命名構詞可清楚還原時，保留描述要素，用自然繁中命名。人工版已有合理且穩定的名稱時優先沿用。
- 構詞中的顏色、外形、棲地、行為、聲音或特殊能力，只有在名稱或原文描述有根據時才能納入。名稱沒有的能力不能自行加上。
- 無法確認構詞時，不為了湊漢字猜造含義。先沿人工版合理名稱，或採一致的音譯並記錄依據；真正影響情節的歧義再查證。
- 網路或字典沒有查到，不足以證明作者自創；標成 `uncertain`，依現有證據選擇忠實譯名。不要為了讓名稱「查得到」而換成真實物種。

分類 `plant`、`animal`、`creature` 的詞彙必填 `origin`，其他類別也可填。值為 `real_world`、`author_created`、`uncertain`。`origin` 記錄來源判定，`decision` 記錄是否已選定譯名；例如不確定現實是否存在，但已能忠實翻譯的名稱，可以是 `uncertain` + `adopted`。

以下是**自造測試例**：若原稿描述「銀色翅膀的狼」，稱為 `은빛날개늑대`，可採「銀翼狼」，不必改成現實的灰狼；`검은비늘꽃` 若命名及描述明確指黑色鱗片狀花瓣，可採「黑鱗花」，不必替換成某種真實藥草。

```json
{"id":"creature-001","ko":["은빛날개늑대"],"zh":"銀翼狼","category":"creature","origin":"author_created","decision":"adopted","basis":"source_description","name_parts":[{"ko":"은빛","zh":"銀色"},{"ko":"날개","zh":"翅膀"},{"ko":"늑대","zh":"狼"}],"evidence":[{"source":"original","block":"s0002:p0005","note":"原文描述銀色翅膀並以此名稱稱呼；此為合成格式範例"}],"definition":"小說中的有翼狼類，不對應指定現實物種"}
```

構詞與分類依據留在詞庫，正文只使用自然一致的中文名稱，不必每次加上韓文、現實學名或查證說明。

## 化名、同名與後文揭露

- 同一韓文可能是不同人物，不能只憑字串做全書取代。
- 後文揭露真名，不代表前文旁白已知道。用 `scope` 限制譯名；正文依當時視角，身份關聯留在工作資料。
- 尊稱可隨說話者、關係與場景變動。必要時記錄稱呼規則，不強迫每個稱呼譯成同一人名。
- 前後稱呼一致指人物身分及稱呼規則一致；例如弟子稱「師父」、旁白用本名可以並存。須區分合理變化與誤換人物，不能機械統一所有叫法。
- `forbidden_zh` 只列在該適用範圍確定錯誤的字樣。正常別名不能列成全書禁字；字串檢查也不能代替語意判斷。

## 依賴與變更

每節 map 的 `term_ids` 包含實際用到及會影響判斷的所有詞彙 ID。工具會檢查原稿出現的已登錄詞形，但無法自動辨認所有變格、代詞或隱含人物。

目前工具綁定完整詞庫列；譯名、證據或適用範圍等欄位改動，都會使依賴它的舊收據失效。相同用法再出現時重用已核定的決策，新出場事實留在該節敘事紀錄或校對 note；資訊確實改變名稱、身分、含義或有原文依據的長期口吻判斷時才更新詞條，並回讀受影響句子。新增無關詞彙不影響未使用它的分節；不能只跑全域文字替換或換指紋就重簽紀錄。

## `continuity.jsonl`

每節一行，記錄讀完該節的敘事狀態，不代替原稿。摘要保持精簡，必要細節由證據定位回原文。

```json
{"section_id":"s0001","summary":"少年在囚牢中等待行刑，尚未得知來人的身分。","facts":[{"type":"viewpoint","value":"第三人稱貼近少年","evidence":"s0001:p0001"},{"type":"knowledge","value":"少年只知道對方是武林中人","evidence":"s0001:p0002"}],"open_threads":["來人的目的尚未揭露"]}
```

保留視角、誰知道哪些事、稱呼、傷勢、位置、持有物、承諾和伏筆。全數排除的前置廣告也要有本節摘要及空 `facts`。工具會將本節及前序敘事狀態綁定驗收，狀態修正後需重查受影響的後續翻譯。
