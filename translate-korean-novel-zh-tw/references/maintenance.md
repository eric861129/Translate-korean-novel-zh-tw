# 維護、異常修復與技能驗證

此文件只在對應情境下閱讀，不納入每節翻譯的固定閱讀清單。正常續譯依 [恢復順序](resume-and-delivery.md#恢復順序)。

| 觸發情境 | 只讀需要的章節 |
|---|---|
| 來源／依據指紋錯誤、快取失效或殘留 lock | [狀態與指紋](#狀態與指紋)、[機械驗證重用](#機械驗證重用) |
| 來源包缺失／損毀、格式遷移或回復 | [來源格式遷移與重建](#來源格式遷移與重建) |
| 舊手工產物需修復，工具未能沿用 | [手工產物格式](#手工產物格式) |
| 修改本技能或驗證工作流行為 | [SKILL 維護](#skill-維護)，此時才讀行為案例及相關程式 |

## 狀態與指紋

- 原稿與人工版使用整檔指紋，變更後停止沿用舊索引。
- 每節收據綁定原文區塊、譯文、逐段對應檔、該節使用的專名及截至該節的敘事狀態。
- 全書收據另綁定 manifest、詞庫、敘事資料、問題清單與全書複核檔；有批次計畫時也綁定全部有效閱讀紀錄的 `batch_reading_sha256`，閱讀依據改動後須重新全書驗收。
- 新增無關專名不使已完成分節失效，但最終全書複核仍需反映最新詞庫。
- 已完成分節內新增可匹配的專名會被視為依賴變更，需核對。其他變格或隱含依賴仍由代理補齊。

不要手改 manifest 的來源索引。若使用者換了原稿，建立新的工作目錄，重新索引，再以原文指紋及內容判斷哪些譯文可搬入，重新驗收後才算沿用成功。

工具對 manifest 使用原子替換，並用 `.writer.lock` 防止兩個工具同時寫入。其他編輯器不會自動遵守此鎖，因此同一工作目錄保持單一寫入者；若主工作階段正在翻譯，不在側邊工作階段改它的進度。

若程序中斷留下 lock，先查明該 PID 已結束，才能移除這一個 lock 檔。不要刪除整個工作目錄或清除尚未判定用途的暫存資料。

## 機械驗證重用

- `context/verification-cache.json` 是可重建的工具快取，與分節資料包一起忽略 Git；不新增逐段報告。首次或失效時完整檢查，成功後才保存結果，快取損毀或缺少時自動重算。快取不是語意驗收、進度或收據的權威來源，不手工填造。
- 每次操作仍讀取原稿、人工版的完整位元組並核對 SHA-256，不以檔案大小或修改時間代替。來源索引與計畫內容完全相同時省去重複解析及統計；計畫驗證只計算需要的字元數。同次操作共用已載入且核對的資料，採單一寫入者及工作鎖。
- 歷史閱讀紀錄逐次比對分節原文索引、譯文與 map 位元組、現有收據、已宣告及新命中的專名、截至該節的敘事資料、適用問題、文體及技能／工具規則；全部相同才重用先前機械檢查。無關新詞、後節敘事或其他分節問題不觸發本節重查；相關變更則重新檢查，失效紀錄不計入完成進度。
- 日常 `next` 只查至最早驗收缺口，回傳的 verified 是有效前綴；`next --prepare` 及 `review-section --prepare-next` 同時檢查連讀缺口，直接帶回分節資料。跨分節章名一致性仍逐一檢查，不只信任有效收據。全書統計使用 `validate`，交付驗證不採此快速路徑。
- 保存／合併不自動補閱讀聲明。`review-section` 對當前分節仍執行完整覆蓋、用語、依賴、六項實際檢查及十項評分驗收；同次操作已檢查的歷史紀錄不再重查一次。交付前的全書驗證完全繞過快取。

資料包的完整詞條與精簡呈現分離：快取及驗收始終使用完整列，閱讀視圖只折疊符合條件的 evidence。`term-details` 以同一 `context_state` 取回原始詞條，不能用過期資料包查新版本證據；compact/full 切換本身不改資料包指紋。風險詞條及所有問題紀錄保留完整資訊，詳細規則以 [日常閱讀視圖](resume-and-delivery.md#精簡詞條與完整證據) 為準。

閱讀包使用 schema 2 的局部依賴，選取與失效契約以 [本節失效範圍](resume-and-delivery.md#本節失效範圍與回查) 為準；不可把此範圍套到分節收據或全書驗證。重新選取本節詞條後才比對完整列，避免漏掉新命中詞。舊格式資料包保守重建並回報差異，不重簽任何驗收。翻譯、指代、專名及評分規則維持在各自權威文件；這份維護說明及操作導覽不作為閱讀包語意依據，若改到語意規則，須同步修改其權威文件。機械驗證快取仍綁定全部規則檔。

人工版僅新增 `context/reference/` 的兩個可重建快取。索引含每 256 行的 Python 文字流定位值，綁定編碼、原檔 SHA-256、Python 主要／次要版本與實作指紋，不能跨版本直接套用。搜尋位置按查詢／數量／游標綁定並限制 32 組；回傳片段前核對實際命中文字，操作前後完整比對母檔指紋。兩個檔案不是校對證據或翻譯進度，詳見 [搜尋與擷取](resume-and-delivery.md#人工版搜尋與擷取)。

v2 的日常路徑在來源與計畫驗證仍有效時，只載入當前小段所屬的原分節。歷史分節的專名命中結果也綁定原文及適用韓文詞形；新增命中詞形時重新掃描，改變既用譯名或依據時仍使對應驗收失效。快取只減少重複解析與機械檢查，不縮減模型必須實際閱讀的原文。

## 舊平行工作轉回單代理

新書與日常續譯均採單一 Session，不建立初譯／查證子代理。現有 `pipeline/` 可能含尚未接收的草稿，依 [舊稿交接](parallel-workflow.md) 在保存點停用；不刪檔、不改已完成進度、不以草稿游標推定完成。`parallel` 只保留交接及中斷保存的相容入口，不再接受新派工。

## 來源格式遷移與重建

新工作 `init` 預設使用約 2 MiB 來源包，實體分包規則見 [來源包與按節讀取](source-and-chapters.md#來源包與按節讀取)。既有 v1 工作可繼續翻譯，不因工具更新而自動改格式。先核對當前工作目錄，再預覽：

```text
python -X utf8 <skill>/scripts/novel_pipeline.py migrate-source --work <工作目錄>
```

預覽不建立包、不修改 manifest、譯稿或進度；完整比對轉換前後的有效／待處理分節、最早缺口及全書連讀紀錄，列出包數與索引大小。原有待處理或失效紀錄如實保留，格式轉換不把它們修成通過。

只有確認同書翻譯任務與編輯器已在保存點停止寫入，才執行：

```text
python -X utf8 <skill>/scripts/novel_pipeline.py migrate-source --work <工作目錄> --apply --checkpoint
```

`--checkpoint` 是對已停止寫入的確認，不會替其他任務暫停。工具取得 `.writer.lock`，重新核對來源、人工版與所有非衍生工作檔，保存 `.migration/manifest-v1.json`，建立並驗證全部來源包後才原子切換 manifest。原稿、人工版、所有 `s`／`p`／`c`／`b`／`d` IDs、計畫、譯稿、對應、有效收據與進度保持原有內容；只因儲存格式不同不重做翻譯。切換後資料包失效，當前節重新 `prepare-section`；既存小段仍依實際內容與依賴核驗。

包寫到一半中斷但 manifest 尚未切換時，仍沿用 v1；確認沒有其他寫入後可重試。不同內容的既有遷移備份不覆寫，先確認前次操作；不批量刪檔，也不增加多份日期版備份。`.migration/` 是本機遷移備份，忽略 Git。已有全書收據、交付狀態或最終輸出檔時拒絕直接遷移，另行安排重新驗收。

來源包是可重建的衍生資料。clone 後缺檔或包指紋錯誤時，確認原始雙輸入路徑可用，執行：

```text
python -X utf8 <skill>/scripts/novel_pipeline.py rebuild-source --work <工作目錄>
```

重建會重新解析原稿、核對精簡索引與全部偏移，只寫入需重建的來源包，不更動譯稿、進度或 manifest。原稿／人工版已改、索引缺節或被重排時拒絕重建；不能用修指紋或還原快取掩蓋來源變更。

若確需回復 v1，同樣在停止寫入的保存點執行 `restore-inline --work <工作目錄>` 預覽，再加 `--apply --checkpoint`。工具使用**目前**來源包和最新收據還原內嵌索引，保留遷移後的翻譯進度；不得直接把舊備份覆蓋回 manifest。回復不刪來源包，也不建立新的最終譯本。

## 手工產物格式

正常工作使用 `submit-chunk`、`merge-section`、`review-section`，由工具產生以下欄位。只有修復舊手工資料時才讀取；手工修改同樣需要真實校對，不直接換指紋沿用舊收據。

### 小段對應與依賴

小段正文放 `chunks/c000001.txt`，只放本段正文，不重複章名、前後文或進度。`chunks/c000001.map.json` 的必填鍵為 `schema_version: 1`、`chunk_id`、`section_id`、`source_sha256`、`translation_sha256`、`alignments`、`term_ids`、`term_dependencies`、`context_before`、`context_before_sha256`、`context_after_sha256` 與 `reviews`。`source_sha256` 取計畫中的小段指紋；`reviews` 用 `fidelity`、`referents`、`fluency`、`locale`、`post_polish` 五項，章名審查與十項評分留到整節。新工具另保存 `style_profile_sha256`，使用資料包時保存 `context_state`。舊 chunk 的 `scorecard` 可保留，但不再要求或重評；section 與全書仍須完整評分。對應及證據規則沿用 [品質與驗收](quality-gates.md)，來源 ID 限當前小段，譯文行號從小段檔第 1 行起算。

指紋計算使用工具的 `digest(canonical(value))`，不要自行更換 JSON 排序或空白規則：


- `term_dependencies` 固定為 `{ "詞彙 ID": "該完整詞庫列的 canonical SHA-256" }`，其鍵集合等於 `term_ids`；無專名時皆為空集合／物件。
- `context_before` 固定為 `{ "previous_section": null, "previous_chunk": null }` 的形狀。`previous_section` 填來源順序中緊鄰前一節的完整 `continuity.jsonl` 列；首節為 `null`。`previous_chunk` 填**同節**前一小段的 `{ "chunk_id": "實際 ID", "state_after": { ... } }`；本節第一小段為 `null`。不是首節卻缺前節狀態時，先從有效譯稿與原文補證，不以 `null` 假裝不存在。
- `context_before_sha256` 綁定上述完整物件；恢復時由目前前序資料重建再比較。`context_after_sha256` 綁定本小段進度的 `state_after`。修改摘要也算依據變更，需重查受影響的後續小段。

### 分節對應

`sections/s0001.map.json` 的例子：

```json
{
  "schema_version": 1,
  "section_id": "s0001",
  "source_sha256": "由 show 取得的原文分節指紋",
  "translation_sha256": "由 fingerprint 取得的譯文檔案指紋",
  "title_zh": "第1章 機會（1）",
  "term_ids": [],
  "scorecard": {"method": "agent_self_assessment", "items": {}},
  "alignments": [
    {"source_ids": ["s0001:p0001"], "disposition": "translated", "target_lines": [3, 3]},
    {"source_ids": ["s0001:p0002", "s0001:p0003"], "disposition": "translated", "target_lines": [5, 7]}
  ],
  "reviews": {
    "heading": {"status": "passed", "note": "填寫實際原文標題、章序與分節核對依據"},
    "fidelity": {"status": "passed", "note": "填寫實際逐段語意核對結果，特別記錄主詞與否定等風險"},
    "referents": {"status": "passed", "note": "填寫說話者、動作者、受詞及你我他她的實際核對結果"},
    "fluency": {"status": "passed", "note": "填寫整節中文閱讀發現與已處理事項"},
    "locale": {"status": "passed", "note": "填寫中國慣用語的語境判定及台灣用語調整結果"},
    "post_polish": {"status": "passed", "note": "填寫潤色後再對照原文的結果"}
  }
}
```

範例中的說明文字不是可提交的證據。指紋、行號與 note 必須換成該節真實資料。`scorecard.items` 必須依 [十項評分規準](scoring-rubric.md) 填滿十項，不能提交空物件；平均未達 85 分不會通過。`target_lines` 是 **1-based、包含端點**的行號；空白行可在區間裡，但不得含標題。

### 手工分節驗收

既有手工流程仍可使用以下命令；`record` 本身不會代填全書閱讀進度：

```text
python -X utf8 <skill>/scripts/novel_pipeline.py fingerprint --path <工作目錄>/sections/s0001.txt
python -X utf8 <skill>/scripts/novel_pipeline.py record --work <工作目錄> --section s0001
python -X utf8 <skill>/scripts/novel_pipeline.py next --work <工作目錄>
```

`record` 檢查區塊覆蓋、標頭、韓文殘留、占位文字、專名範圍／禁用譯名、未結問題、簡體與地域字詞清單、十項評分及校對紀錄。標題、語意、主詞指代、流暢度、台灣用語及潤色後回查都須有實際結果；這些項目可在相同閱讀流程中檢查，不要求各自呼叫模型。通過後保存綁定指紋的收據。任一譯文或 mapping 改動都需要重新核對與記錄；不能只把舊指紋換成新值。`next` 只是查詢整節進度；完成內部工作單位 `b` 後，依計畫繼續同一交付批次 `d`。整個 `d` 有效完成後，全書任務保存並接續下一批，指定範圍任務依其上限收尾。

## SKILL 維護

只在修改本技能時檢查案例與對應實作。保持主入口及各階段連結可達；來源與切分規則以 `source-and-chapters.md`、日常操作以 `resume-and-delivery.md`、驗收與交付以 `quality-gates.md`、評分以 `scoring-rubric.md`、專名及文體以各自文件為準。調整內容時更新原定義與引用，不複製一份新規則。

文件重整先檢查 UTF-8、連結與情境閱讀順序；工具或資料契約變更再執行適用回歸測試：

```text
python -X utf8 -m unittest discover -s <skill>/scripts -p "test_*.py" -q
```

需要查程式時，CLI 入口為 `novel_pipeline.py`，產物流程為 `chunk_workflow.py`、舊平行草稿交接相容工具為 `parallel_workflow.py`、分節資料包為 `section_context.py`、局部依賴與差異為 `context_dependencies.py`、人工版定位為 `reference_store.py`、詞條閱讀視圖為 `terminology_view.py`、機械驗證快取為 `verification_cache.py`、來源儲存為 `source_store.py`。正常翻譯直接執行 CLI，不把全部程式或測試檔讀入模型上下文。

文件與工具更新依各快取的依賴範圍判定失效，在完整保存點重新準備資料並核對變更；不重設小說進度或替其他正在翻譯的任務遷移格式。其他任務需自行重新讀取新規則，不能假設已即時套用；交付前按變更核對適用的舊稿。案例及工具測試只能驗證流程行為，若要聲稱翻譯品質或速度改善，另以相同章節比較實際閱讀量、操作耗時與漏譯／指代／專名錯誤。

### 行為驗證案例

建立或修改本 SKILL 時，除程式測試外，逐項檢查指令是否能導引以下行為：

| 情境 | 應採取的行為 |
|---|---|
| 人工版把功力成數寫成星等 | 回讀原稿判定語意，記錄譯名修正 |
| 來源章號延續方式不規則 | 保存原始結構並核對，避免自動重編 |
| 潤色刪了「沒有」但中文仍順 | 語意回查須指出否定翻轉；機械檢查本身不能證明此點 |
| 對話換人但下一句仍把「我」指向上一人 | 依當下說話者與聽話者修正代詞 |
| 配角隔多章再登場，人工版用了近音異名 | 依原稿身分及既有詞庫判定，不漏掉配角或誤合併人物 |
| 「信息」可能指密探送來的內容 | 依語意選「情報」或「消息」，不機械換成「資訊」 |
| 初稿已通順，使用者估計約完成 85% | 保留好句、修正細節；仍覆核全書，不虛構品質分數 |
| 十項平均 84.99，顯示時可四捨五入成 85 | 保持未通過，修訂後重新評分 |
| 平均 90，但對話中的你我已確認譯反 | 先修正並解決問題，不能靠平均分數交付 |
| 名字屬於偽裝身分 | 維持當前視角稱呼，後文真名不污染前文 |
| 名稱為自創的有翼狼，查無真實物種 | 依構詞和原稿描述譯名，不替換成灰狼；查無結果不單獨用作自創判定 |
| 藥草性質與真實植物接近，但名稱不同 | 保留原作名稱意義，不能僅憑藥效替換為現實藥材 |
| 程式通過但未執行韓文校對 | 不建立真實語意驗收聲明 |
